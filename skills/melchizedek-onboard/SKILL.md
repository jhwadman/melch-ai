## What this skill does

It turns "what do you have?" into one of ten authentication levels and the startup guide for it. The guides are generated by the engine itself, so you print them instead of restating them:

```bash
npx melchizedek-setup --list                 # the ten levels
npx melchizedek-setup --level <id|number>    # one level's guide
npx melchizedek-setup --auto                 # detect from the environment, names only
```

In a clone of the repository, use `npm run setup -- <flags>` instead of `npx melchizedek-setup`. The same guides are in `ONBOARDING.md`.

## The rules that never bend

- Never ask the person to paste a key, token or secret into the chat, and never read one from their files or shell history. A pasted key lives in the transcript forever.
- Never print a value from `.env`. To check what is set, run `npx melchizedek-setup --auto` or `npx melchizedek-doctor`; both report names and set or unset only.
- The person types every value into `.env` in their own editor. You may create `.env` with names left blank: `npx melchizedek-setup --level <id> --write-env`. It never overwrites an existing `.env` and refuses unless git ignores `.env`.
- Never reuse another app's sign-in (the Codex CLI's login, Claude.ai, Gemini CLI) as a model credential, and never read its token files. Route that person to level 10, which names the sanctioned alternative.
- A ChatGPT plan is used only through the engine's own Sign in with ChatGPT (level 9): the person runs `npx melchizedek-setup --chatgpt-signin` and approves in their own browser. It is for their own machine only; never set it up for a server.

## Triage

1. Run `npx melchizedek-setup --auto`. If it already detects a level beyond 1, confirm with the person that this is what they want and continue from that guide.
2. Otherwise ask one question: "What do you have: nothing yet, an API key from a model provider, a gateway key, cloud platform access, a ChatGPT plan, or a Claude or Gemini sign-in? And will other people or backends call your agents?"
3. Route by the answer:

| They have | Level | Follow |
|---|---|---|
| Nothing, or want everything on their machine | 1 `local` | `melchizedek-onboard-local` |
| One key from Google AI Studio, Anthropic, OpenAI, xAI or Moonshot | 2 `one-provider` | `melchizedek-onboard-keys` |
| Keys from several of those | 3 `several-providers` | `melchizedek-onboard-keys` |
| A Vercel AI Gateway or OpenRouter key | 4 `gateway` | `melchizedek-onboard-keys` |
| Google Cloud (Vertex AI), AWS (Bedrock) or Azure OpenAI access | 5 `cloud-platform` | `melchizedek-onboard-cloud` |
| Callers who fund their own model calls | 6 `byok` | `melchizedek-onboard-serve` |
| Other backends or users calling the server | 7 `caller-tokens` | `melchizedek-onboard-serve` |
| Tools that act for each user on a third-party API | 8 `oauth-grants` | `melchizedek-onboard-serve` |
| A ChatGPT plan, to use on their own machine | 9 `chatgpt-signin` | `melchizedek-onboard-keys` |
| A Codex CLI login, a Claude.ai or a Gemini CLI sign-in only | 10 `subscription-signin` | `melchizedek-onboard-keys` |

Levels 6 to 8 sit on top of a model level (1 to 5): settle how models are paid for first.

4. Print the level's guide with `--level <id>` and walk it step by step: the person sets the variables, you run the doctor command the guide names and read its verdicts back to them, then you run the first command.

## Done when

The doctor shows the level's confirmation (the guide's **Confirm** line), and the first command has answered once. Then hand over to the `melchizedek` skill for the catalog of syndicates.
